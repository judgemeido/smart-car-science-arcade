# 科学小游戏：GitHub 技能核验与视觉方向附录

日期：2026-11-08。状态：规划附录，供主计划引用；尚未进入产品实现。

本附录只研究原始 GitHub 技能和明确视觉验收标准。目标是让三至六年级儿童在各自电脑上玩有操作、有挑战、有即时反馈的科学小游戏：01 主题卡牌／游戏，02 结构挑战，03 传感器实验室。三个页面属于现有 01–04 导航分组中的独立入口，分组使用手风琴导航。每个儿童独立使用本机本地存储，通过相同挑战码进行同题挑战，再比较各自真实结果卡；本机也记录个人纪录。

后续全部产品实现由 GPT-6.1-sol 执行。本附录保持规划状态，不授权立即开始实现。

本轮已读取本地 frontend-design、原始仓库的六个 SKILL.md、两个 Game Studio 参考文件，以及可取得的许可证／插件元数据；未安装技能、运行外部技能脚本、添加依赖、修改产品代码或提交 Git。这里的“采用”指规划中采纳经核验的工作方法，不能据此宣称已安装 Game Studio 或已经试玩实现。

## 4. 渲染方式建议与取舍

推荐：**DOM 页面与控件＋SVG 真实对象图解＋局部 Canvas 的科学效果**。主计划仍负责路由、生命周期、状态、存储和模块边界。本节仅提供与玩法呈现相关的取舍，不规定一套额外架构。

| 页面 | 首选画面与操作 | 局部 Canvas 用途 | 升级 Phaser 的条件 |
| --- | --- | --- | --- |
| 01 主题卡牌／游戏 | DOM 卡牌、SVG 科学对象、匹配槽／事件轨道；翻看、归类、排序、提交、连胜反馈 | 可选的短时结算粒子；没有就不需要 Canvas | 改为连续移动角色或复杂精灵场景，超出卡牌操作 |
| 02 结构挑战 | SVG 汽车剖面／装配架与可辨识部件；吸附、连接、旋转少量零件、启动结果检验；DOM 工具托盘 | 启动后的短轨迹／能量流或大量粒子，核心连接关系仍来自同一规则状态 | 成为连续可驾驶关卡，需要相机、碰撞与平台／地形系统 |
| 03 传感器实验室 | SVG 路段、车辆、行人、树／路障、米刻度与测量标注；拖动目标、调参、开始扫描、比较预测与测量 | 点云／光脉冲／雨雾的高频绘制，暂停后保留关键测量结果 | 传感器任务变为完整连续躲障动作游戏，而非实验操作 |

SVG 图形与可访问控件应有对象名称、稳定选中态和键盘路径。Canvas 不能成为唯一信息源：测量数值、判定、选中目标、单位与操作按钮仍可读取、聚焦。图像中的位置、刻度和评分必须来自同一数据，避免“看起来很远”而规则说很近。

游戏性由明确目标、约束、操作、可观察结果、策略改进和挑战节奏决定。仅加背景动画、经验条或积分数字，并不能将选择题面板变成科学游戏。

## 5. 推荐美术方向：彩色科学游乐场与插画实验桌

主计划已选择“彩色原创 SVG 科学游乐场＋插画实验桌”作为推荐提案：清爽、明亮、色彩丰富，适合儿童又保持讲解可信度。该设计仍待用户审核，不能写成用户已批准的品牌规范或实现授权。

### 5.1 视觉主角与材料语言

主角是“正在发生的实验”：01 桌面上可翻看／移动的科学卡牌；02 有部件槽位、连接和启动反馈的汽车装配架；03 真实目标与清楚刻度的传感器路段。汽车、电池、轮胎、悬架、镜头、雷达和光束形态要能辨认，不能用几何色块和 emoji 代替所有科学对象。

采用同一组原创 SVG 插画：圆润但明确的物体轮廓，2–3 px 深色描边，少量分层阴影，白色／冷色台面，彩色夹具、工具槽和标签。投影仅用于“可移动的部件／卡牌”；实验台面与说明不重复相同卡片阴影。按钮可有轻微实体按下反馈，页面不用密集玻璃效果和无意义霓虹渐变。

专业感来自物体比例、对齐、空间、统一轮廓和明确状态。趣味来自玩家直接改变这些物体以及得到可读的科学结果。吉祥物若使用，只在短引导或结算出现，不占主要操作区。

| 观察青绿 | `#007F78` | 测量完成、连接正确、有效操作 |
| 动力橙 | `#F87537` | 电池／能量路线、正在实验、挑战工具 |
| 奖励明黄 | `#FFD36A` | 奖章、连胜、提示强调、小面积庆祝 |

补充白色 `#FFFFFF` 作为台面；错误使用语义色并同时显示文字／图标。橙黄区域优先用墨蓝文字，不能凭肉眼假设白字达到对比要求。正文与按钮普通文字对比至少 4.5:1，焦点和必要图形边界至少 3:1；实现时验证真实配对。相同语义跨页使用同一颜色；各页差别来自对象与布局，避免每页重造配色。

### 5.3 字体与尺度

中文优先一个清晰、圆润但不幼稚的无衬线体系。实现时可选择本地提供的 Noto Sans SC 字体资源；如果没有已许可的本地字体资源，先用 `"Microsoft YaHei", "PingFang SC", sans-serif`，无需外部字体请求。字体是否下载与许可在实现时检查；本轮未下载。

| 角色 | 桌面建议 | 窄屏建议 | 约束 |
| --- | --- | --- | --- |
| 页面名称／关卡大标题 | 32–40 px，700–800 | 26–30 px | 一至两行，完整标题统一处理 |
| 当前任务目标 | 22–24 px，700 | 20–22 px | 一句话说明本轮要做什么 |
| 正文／按钮 | 至少 18 px，500–600 | 至少 18 px | 1.5–1.65 行高，不用小号灰字传达规则 |
| 图解／单位／辅助标签 | 至少 16 px | 至少 16 px | 科学名称与米、秒等单位一直可见 |
| 得分／测量数字 | 24–28 px，700 | 22–24 px | 等宽数字方便变化比较，数字与单位相邻 |

不要以等宽开发字体作为全部数据／标签字体，不给中文导航强加英文全大写标签。说明一块只讲一个动作或一个原因，短句为主，长知识说明收进“为什么？”或“实验笔记”。

### 5.4 页面空间与导航

桌面初始画面以实验桌／游戏区占主体区域约 60–70% 为设计目标。左侧导航较窄，保留现有 01–04 分组与子页面，当前子页面有形状和文字标识；打开一个分组不会清空正在进行的挑战。小屏收成可操作的导航抽屉，页面顶部只保留返回／页面名称和紧凑状态。

建议共同骨架：

```text
┌──────────────┬──────────────────────────────────────────┐
│ 01–04 分组   │ 页面名称        本轮进度／个人最高分       │
│  可展开子页  ├──────────────────────────────────────────┤
│  当前入口    │ 一句话任务              提示／暂停操作     │
│              │                                          │
│              │         主要科学游戏操作区                │
│              │    卡牌桌／汽车装配架／传感器路段          │
│              │                                          │
│              ├──────────────────────────────────────────┤
│              │ 当前工具或部件托盘     明确主行动按钮       │
└──────────────┴──────────────────────────────────────────┘
```

这是共享空间关系，不要求三页成为同样卡片排列。01 可呈卡牌轨道与归类槽；02 用剖面装配架与零件托盘；03 用道路与仪器面板。右侧长知识面板默认不展开。第一次进入应能在一个清晰行动后开始游戏，无需先读多段说明或经过多层选择菜单。

### 5.5 三页物体与科学反馈

| 页面 | 必须出现的可辨识对象 | 操作结果的可视化 | 防止退化为选择面板的标准 |
| --- | --- | --- | --- |
| 01 | 与主题相符的汽车／电池／传感器卡图、归类槽或事件时间轨道 | 卡牌进入槽位后立即显示关系；正确后简短因果解释，下一轮出现新组合 | 至少一种归类、匹配或排序动作直接改变桌面；普通知识卡与挑战轮次可区分 |
| 02 | 清楚的电池、电机、底盘、悬架、轮胎和对应连接／定位关系 | 放置与连接改变装配架；启动后用轮动／能量路径检验装配结果，错误指出具体缺口 | 玩家完成对象操作再做结果检验；不能仅点击部件名后答选择题并宣布装好 |
| 03 | 摄像头、激光雷达、毫米波、超声波的可辨识图形；车、行人、树、路障与米刻度 | 改目标或条件后测量、回波／点云及可靠性显示变化；预测与测量并排对照 | 至少一个控制改变实验条件且实际影响可观察结果；所有显示与评分使用同一简化模型 |

图解使用“示意”标识时要简短，不把简化的覆盖扇形／雨雾效果当作真实设备标定数据。不同传感器的作用和局限以既有审核内容为依据；不能把模拟结果画成“任何天气都一定可靠”。“没有识别到”与“确认没有障碍”应是不同画面和反馈。

### 5.6 动效、音效与节奏

- 反馈优先即时：选中／聚焦立刻出现轮廓与标签；按钮按下 100–160 ms；卡牌／部件有效落位 180–260 ms；扫描反馈以可观察步骤呈现，练习模式可暂停或分步观看。具体时长以试玩调整，不强求所有元素同一种动画。
- 错误时保留上下文，指出“电机还没连接电池”或“看一下刻度再测量”，提供重试；不依赖剧烈震屏、嘲讽文字或只能靠颜色理解的红光。错误拖放回原位，合法目标继续可见。
- 奖励使用短促光圈、印章／奖章和少量 350–600 ms 庆祝；结算说明本次策略改善，强庆祝主要留给关卡完成。避免循环闪烁、满屏粒子和持久遮挡科学图解。
- 音效提供轻触、连接、测量完成和过关四类短声音。初始静音，有明显声音按钮，用户操作后才启用并保存本机偏好。静音时每一结果都有等价视觉／文字反馈；不使用持续背景音乐掩盖讲解。
- `prefers-reduced-motion` 下去掉粒子、震屏、视差与非必要转场；扫描可用静态分步高亮和数字更新表达，位置变化可以瞬时或短过渡完成。暂停操作、导航离开或页面隐藏时停止动效和游戏输入；正式挑战的 360 秒倒计时继续，不能借此延长挑战。返回时按真实截止时间更新剩余时间；已到期则呈现真实结算结果。
- 正式挑战开始前明确显示“360 秒，暂停操作和离开页面仍会计时”；操作暂停入口标为“暂停操作”，暂停态再次提示“倒计时继续”。练习模式无时限，可以使用“暂停练习”。计分细则归主计划，不因减弱动效、静音或使用键盘降低得分。

### 5.7 同题挑战码与真实结果卡

儿童在各自电脑输入相同挑战码，获得可比较的同题挑战。结算显示该挑战码、规则版本、本人真实得分与完成情况，并保留“我的最高分”“比上次进步”等本机反馈。实际比较由儿童或老师查看各自结果卡完成；每张卡只呈现本机真实挑战结果。玩家昵称如需输入仅存本机，不用登录。界面不生成机器人对手、虚构竞争分数或班级联网排名。

提示助手仅负责简短引导和下一步，不参与竞赛得分，不自动把正确答案贴在操作目标上。若主计划安排基于规则的模拟 AI 指导，应与实验数据一致，并在帮助后仍要求儿童操作和判断。本附录没有设计真实模型请求、API 密钥或网络排行榜。
