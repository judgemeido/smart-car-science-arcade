# 01–04 闯关式学习内容设计

状态：用户已授权实施；实现与验收记录见 `docs/engineering/upper-primary-learning-progress.md`。日期：2026-11-08。

## 1. 目标与范围

将现有四个展厅串成“认识汽车→理解结构→感知实验→安全决策”的学习路线，让小学五至六年级学生在操作后说出理由。沿用已完成的内部拆分，新增内容归入原章节，原浏览与小游戏入口继续可用。

用户已经明确页面服务最终用户，当前重点是保留现有体验，并让内容和小游戏便于修改。因此，本期细化 01–04；材料中的 05 设计、06 测试、07 实体制作只进入后续路线图。本稿不把“根据材料生成 Plan”解释为已经授权新增这些章节或实施代码。

本次来源：用户最新提供的课程材料，以及 [五六年级内容包](../../content/2026-11-08-upper-primary/README.md)。单选题、解释、目标引用与资源缺口以四份 JSON 为内容起点。旧内部整理计划已完成，本稿不重复安排重构。

## 2. 方案选择

推荐“原展厅加章内学习任务”：先接入引导与复习，再添加有明确开始、反馈和完成状态的新挑战。学生可自由逛展，也可跟随任务前进；完成一章后给出下一章建议，导航不锁定。

直接替换原展厅会同时改变题目、节奏和学生熟悉的操作，回归范围较大。一次加入设计、测试与统一存档会引入新的业务接口和素材需求，适合另立设计。本期采用推荐方案。

## 3. 全局约束

- 面向小学五至六年级；每个任务一个核心问题；必要术语有一句解释。
- 章节 ID 保持 `history/explore/lidar/traffic`，编号保持 `01/02/03/04`；现有导航与 hash 保持兼容。
- 保留现有 14 展品、原 `BatteryPack→ADAS→Cabin` 三任务、雷达 8 部件/4 步/5–80 米/720 点示意、道路原 8 情境与 8 分结果。
- 保留旧流程的 02 五秒动力故事、03 每步 1.3 秒、04 的 2300 ms 反馈/4.8 秒过街/550 ms 过街后反馈和后台暂停语义。
- 新增反馈由学生读完后主动继续；新任务重置与原玩法重置分别处理。
- 内容与纯规则不导入 DOM/Three.js；控制器连接状态、界面与场景，不另外维护分数或完成状态副本。
- 不新增框架、后端、登录、云存档、依赖或通用游戏引擎；沿用 TypeScript、Vite 6、Three.js 0.180、Vitest 4.1.12、Playwright 1.56.1。
- `mount(host)`、`load(host, signal?)`、`setActive/dispose` 保持兼容；使用现有 scope、暂停计时与资源释放工具。
- 所有选择按稳定 ID 判断；未知 ID 不改变状态；答案顺序变化不改变正确性。
- 触屏、鼠标和键盘都能完成任务；输入文本按文本显示；不以拖动为唯一操作。
- 成果保存在当前已挂载控制器的内存中；普通切章保留，刷新、控制器重建或页面退出后重置。本期不承诺持久保存。
- 原 8 分与扩展完成反馈分开展示；本期不加入 100 分、首答计分、连续奖励和章节门禁。
- 学生界面只出现学习内容、操作与必要示意说明；开发说明留仓库。

## 4. 01 认识汽车

先加入 5 张主题卡及章首引导，保留中国新能源展品原资料与图片许可。早期动力和生产属于补充主题，不把现有馆藏包装成完整世界汽车史。

新增三个任务：五事件年代排序、三题生活问题与技术匹配、四选一未来技术与理由。排序既可拖动，也可“选卡片→选位置”；提交后反馈，顺序错误可调整。匹配题允许纠错，正确反馈后主动进入下一题。

未来表达选择没有唯一正确观点。理由去除首尾空白后按 Unicode 字符计数，范围 10–120；长度仅作完成条件，不自动评价内容质量。完成条件：排序正确、三题均完成正确理解、未来选择有效且理由长度有效。知识卡呈现事件、技术解释和学生理由。

## 5. 02 拆解汽车

先在原三任务后加入三题功能复习，并修正“所有设备发探测信号”的表述。摄像头接收道路图像，雷达与激光雷达主动探测。

新增独立“结构挑战”：动力 4 项、基础结构 4 项、感知 5 项，共 13 项。每项先根据功能找目标，再回答功能问题，满足命中与问答条件后主动进入下一项。已正确完成的任务只登记一次。挑战内暂不显示目标名称，完成后揭示；自由观察继续显示原资料。

子节点命中从实际网格沿祖先链向上匹配，优先匹配当前题允许的最近节点，不直接把全部拾取提升为顶层装配。底盘任务需至少一处前/后悬架和制动系统；两处悬架不能代替制动。

毫米波雷达没有独立命名 GLB 节点。使用明确标注教学示意的卡片热点 `teaching-millimeter-radar`，不能以“点到真实零件”记录它。模型失败时允许通过相应部件图文学习完成替代任务，并在报告标明“图文学习”。

可选扩展是四步分组归位：底盘→动力→车身座舱→智能设备。它是教学演示，独立于核心挑战完成条件；不代表工厂装配流程，不做精确三维拖放。

## 6. 03 感知世界

先低龄化现有部件/步骤说明，加入 20→60 米观察与 6 张传感器卡。光往返时间沿用现有函数，分别约 133.4 ns、400.3 ns，学生只比较变化。

新增独立实验区域，展示汽车、行人、树、路障四种教学几何目标及对应点云。点云来自教学模型，不宣称真实扫描或识别。距离定义为传感器参考原点到目标参考标记的直线距离，几何与计算读取同一份米制数据；场景显示缩放不参与测距。

距离挑战先使用三轮固定数据，先选最近目标和距离档，再提交揭示精确值。区间为 `[0,10)`、`[10,20)`、`[20,40]`，10 米归第二档、20 米归第三档。题目未提交时，标签、辅助说明和结果区域均不出现精确答案。错误后可重试，答对后主动继续；本期不做随机生成和连胜奖励。

天气实验在同一目标布局上切换正常/雨/雾，使用可复现的定性示意。三种情况都能读说明和回答三道局限题；不显示虚构设备识别率、真实探测距离或固定性能退化百分比。GNSS 用于定位，不能据此识别行人。

实验记录列出 20/60 米原理对照、三轮实际选择与结果、对应天气题的安全建议和所选设备卡的作用与局限，不生成学生未输入的个人理由。旧雷达模式、扫描和重置保持独立。

## 7. 04 安全决策

原八题继续完整使用，结束后可打开复习卡，回看观察线索、选择解释和小结。复习通过原场景及选择 ID 关联，不复制原题答案。

新增独立进阶挑战：绿灯无冲突、突然横穿、前方障碍、暴雨、感知信息不可靠，共 5 题。每题使用“观察→决策→反馈→总结”；原八题不会因为新增长文改为四步流程。

每题先播放或展示情境，学生主动进入判断；选择后展示行动或风险示意与解释。错误允许回到决策重试；答对后进入总结，学生主动进入下一题。重复点击无效；只有全部五题掌握后显示进阶完成。任何新流程都不发送原八题的答题事件或增加其分数。

新场景进入入口只在原路线准备或完成阶段出现，避免中断旧题反馈计时。退出进阶后恢复原道路场景和视角。复用当前 renderer，通过独立场景组显示新情境，不再创建一套无关车辆驾驶系统。

动画与给定条件一致：突然横穿具备停车条件；障碍情境邻道安全未知；暴雨表示湿滑与视线下降；感知异常表示信息不可靠。错误反馈以风险区域和路径说明为主，不靠碰撞动画奖励错误选择。

## 8. 成果、可靠性与审核

四章各自呈现章内成果卡，用现有导航建议下一章；不建立跨章节统一成绩。普通切章保留本页草稿，控制器销毁后清理事件、计时器和 GPU 资源。模型失败仍可读新题与解释，恢复或重建不重复登记成果。

开工先运行现有 `npm run check` 建立当时基线，不能以旧通过记录代替。新增纯状态测试重点验证 ID、重复操作、区间边界、组合命中与阶段门控；浏览器测试验证学生完整流程、输入方式、切章、降级和清理。完成后再执行全套检查。

史料沿用现有来源，本稿不新增精确历史断言；新插图默认使用现有素材或项目内程序几何，需新增外部素材时先记录来源与许可。50 分钟仅来自原文教学建议，不作为开发工期或课堂效果承诺。
