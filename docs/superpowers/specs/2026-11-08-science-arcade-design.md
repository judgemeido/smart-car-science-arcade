# 01–03 科学游戏与分组导航改造设计

日期：2026-11-08。状态：**方案，产品实现尚未开始**。本设计与[总实施计划](../plans/2026-11-08-science-arcade-plan.md)共同交付；用户要求先看方案。当前代码基线为 `codex/modular-reliability` 的 `61d50c7`。

## 1. 本轮目标

把现有 01 主题学习、02 结构挑战、03 传感器实验室变成三个独立、可以亲手操作的二维科学游戏。学生通过摆放、连接、发射、测量、试运行和修正完成任务。原有展厅继续承担观察展品的作用，新游戏承担操作与挑战；两类体验在同一章节下可发现、可来回切换。

用户本轮确认覆盖早期方案的条件：面向小学三至六年级；各自使用一台电脑；记录保存在本地；现场需要比较游戏表现；主负责人控制核心架构、接口、质量与协作流程，其余规划和实现交给 **GPT-6.1-sol**。本轮范围是 01–03 与共同导航，不增加 05/06。

“假评分、假 AI”落实为可解释的游戏积分、徽章动效和有角色形象的脚本提示助手。助手根据玩家本局操作给提示，可说“回波到了，试试接到接收口”；界面称“提示助手”，不声称理解自由作文或进行真实智能测评。正式分来自实际操作；其他电脑上的同学成绩由本人展示，不生成虚构同学或班级榜。

## 2. 信息架构和导航

**用户最新校正：独立页面，通过顶部不同按钮切换。** 章节分组只组织导航，不把两个页面排在一起。尤其 02：点“拆解与交互”后整个主内容区只有 3D 展厅；点“结构挑战”后整个主内容区切换为独立 2D 游戏。挑战不是展厅右侧面板、下方附加区、弹窗或内嵌手风琴。01、03 同样执行这一页面边界。

```text
01 发展历史
   ├─ 发展历史               #history
   └─ 主题卡                 #history-lab（页标题：进化修复站）
02 结构展厅
   ├─ 拆解与交互             #explore
   └─ 结构挑战               #structure-lab（页标题：系统维修台）
03 激光雷达
   ├─ 感知原理互动展         #lidar
   └─ 传感器实验室           #sensor-lab（页标题：回波侦探）
04 安全上路
   └─ 中国道路规则体验       #traffic
```

`nav#chapter-menu` 保留，内容改为四组手风琴。四个组头均为 button，点击仅展开/收起；子项为带真实 hash 的链接，点击进入独立页面。04 也显示同样结构，展开后只有一个子项，避免同一外形的组头具有不同动作。默认展开当前路由所属组，每次选择其他组关闭上一组；允许全收起。路由变化时自动展开当前组；当前子项有 `aria-current="page"`，组头可高亮但不冒充当前页面。

子项在顶部导航中绘制成清晰的按钮：“拆解与交互”“结构挑战”是两个并列页面入口。实际使用链接语义以支持地址、后退和新标签打开，外观与操作符合用户所说的不同 button。手风琴展开的仅是入口按钮；页面内容始终在导航之外的唯一主内容区显示。允许已访问页面保留内存状态，但非当前页必须隐藏且 inert，不能同屏出现两个工作台。

桌面保留项目的顶栏/导航位置，四组在原导航区域排列，子项在组内展开并占据布局空间，不覆盖游戏工具。窄屏由现有菜单按钮展开纵向导航。组头提供 `aria-expanded/aria-controls`，关闭的列表 hidden；Tab 逐项聚焦、Enter/Space 切组、链接 Enter 导航。Escape 关闭移动菜单并把焦点交还菜单按钮；主动点子链接进入时把焦点送到页面标题。初次载入、后退/前进不强制抢焦点。

总章数始终为 **04**，当前编号随所属组而变，不因七个页面显示 07。旧四个 hash、章节内原有下一章链接保持含义；新游戏的“返回展厅”指向同组旧入口。深链接、无效 hash 回退、浏览器前进后退、加载失败重试都沿用现有路由机制。

## 3. 三款游戏的实际变化

| 页面 | 玩家在画面中做什么 | 结果怎样反馈 | 科普收获 |
| --- | --- | --- | --- |
| 01 进化修复站 | 把五辆事件车排回时间轨道；给工厂/补能/道路场景组装需求到技术的关系；拼出未来车的“用途—能力—条件”说明卡 | 小车沿修复轨道运行；流程模块连通后出现生产/能量/信息流；错误只标出需修正的一段 | 技术随需求发展，多种能源与能力并存，设计需要说明条件 |
| 02 系统维修台 | 在动力、支撑、感知三张汽车剖面上补齐部件；连接有方向、有含义的功能关系；按试运行检验 | 电机转、悬架活动、车轮与路面接触、传感器信息进入分析区；错件/错线保留供局部修复 | 认识原有 13 个主题，理解部件之间怎样配合；图示不冒充真实维修或模型命中 |
| 03 回波侦探 | 转发射器、发射脉冲、接收回波；扫描不同方向、读取证据并移动距离尺；在雨雾中连接传感器信息并设置观察行动 | 回波路线、逐渐出现的轮廓、单程/往返距离、米制标记、天气前后证据可见变化 | 光程与距离、点组成轮廓、信息缺失与局限、传感器互补 |

每页只保留两至三个核心机制。基础循环是“短目标 → 操作对象 → 试运行/确认 → 看到因果 → 局部修正 → 主动继续”。选择按钮可以作为操作工具，成功判定必须来自玩家改变的排列、装配、连接或实验参数，不能只把旧单选题包上游戏外观。

教程在正式计时外，用非正式示例教一次操作；主任务约三至六分钟。练习不限时、可重做；正式挑战默认六分钟。这些是待试玩的设计参数，不是已验证的儿童完成时间。两档 `guided`（引导，建议三四年级）与 `standard`（标准，建议五六年级）改变引导密度、干扰项和明确的输入容差，科学事实一致。各档单独比较，不采集实际年级。

## 4. 美术和体验标准

方向采用**彩色科学游乐场与插画实验桌**：明亮、可辨识、有可操作物件的质感。三页有共同的字体、按钮、提示助手、进度与结果卡，但台面构图各不相同。

- 背景 `#F3F8FC`、文字 `#173653`、主操作 `#2352CF`、成功 `#007F78`、能量 `#F87537`、奖励 `#FFD36A`。文字/状态用实测对比度校验，浅色奖励面上使用深色字。
- 正文和按钮至少 18px，辅助标签至少 16px，任务标题 22–24px，页标题 32–40px；中文优先使用本机可用字体，不依赖联网字体。
- 中央台面承担主要视觉面积，桌面目标约 60–70%；短目标在上、工具托盘在下、长知识放资料抽屉。1366×768 与 1440×900 可见任务和主操作，不需先滚过长说明；窄屏改分区堆叠，不等比压缩整个台面。
- 原创 SVG 绘制能认出的电池、电机、齿轮、悬架、轮胎、车辆、雷达和工具，采用统一线宽、圆角与有限阴影。不能用 emoji 或无辨识度矩形代替主体插画。
- 动效用于落位、连通、回波、纠错和完成；没有动作时页面安静。音效默认关闭，由学生主动开启；音画都不能成为唯一反馈。减少动画模式有静态等价状态。
- 拖拽均有“选对象 → 点目标”的等效路径，键盘可完成全局；至少 44×44px 的操作目标，局部更新保留焦点。颜色之外还须有文字、形状和方向。

先完成一个“对象操作—错误修正—成功—结算”的真实可玩片段，用截图和试玩确立质感，再并行扩展三页。模板漂亮但动作不改变场景，不通过此关。

## 6. 公共技术边界

继续使用原生 TypeScript、Vite、DOM、SVG。Canvas 仅承接确有需要的高频点云/粒子；新页面直接进入时无需 Three 或旧模型。Phaser 暂不成为产品依赖；只有玩法改成连续精灵移动/碰撞等且小样证明更合适时才另行调整设计。

`src/app/chapters.ts` 导出七个扁平 `pages` 与从它们派生的四个 `chapterGroups`。沿用 `ChapterController.setActive/dispose`、hash 路由和 runtime 的惰性加载/故障隔离，不另建路由器。每页持有自己的 `ArcadeSession`；共享 session 统一管理事实去重、时间、成绩和保存，UI 不自行计分。

```text
app: pages + chapterGroups → shell / navigation / runtime
  ├─ chapters: history / explore / lidar / traffic（原展厅）
  └─ activities: history-lab / structure-lab / sensor-lab
       ├─ content + pure reducer（领域规则、事实）
       ├─ view + controller（画面与输入）
       ├─ shared/arcade（session、scoring、storage、challenge-code）
       └─ ui/arcade（开始、HUD、提示助手、成绩卡）
content/* + shared pure rules ← 原展厅与新游戏共同引用
```

## 7. 本地比赛和公平比较

每游戏满分 1000：完成贡献最多 700、首次正确贡献最多 200、完成后的时间奖励最多 100。目标权重合计 1000；纠错后仍获全部完成贡献；查看明确答案提示会失去该目标首次正确贡献。缺输入、拖动过程、重复按钮和连对动画不加减分。自由文字只展示，不打质量分。

令 `E` 为完成目标权重、`F` 为首次实质确认正确且未用答案提示的权重、`t` 为耗时毫秒：

```text
P = floor(700 × E / 1000)
Q = floor(200 × F / 1000)
H = 全部完成 ? floor(100 × clamp((360000 - t) / 180000, 0, 1)) : 0
S = P + Q + H
```

比赛默认 `durationMs=360000`，180 秒内全部完成获得完整时间奖励。全部首次正确且 270 秒完成得 950 分；先错后修复权重 200 的一项、270 秒完成得 910 分。相同事实与耗时必得相同分；计时来自单调时钟。完成/时间到有效，主动结束/刷新中断不作为可比成绩。练习显示完成和证据，`score/elapsedMs` 为 null。

老师公布挑战码，例如 `SA1-R07-7K2M4C-G`：同码固定种子、任务/目标、档位和容差，G/S 对应引导/标准。比较键固定为 `activityId + challengeCode + profile + contentVersion + scoringVersion + durationMs`。本期分别比较三款游戏，不做混合总榜、自动跨电脑同步或教师聚合系统。

每台电脑显示本轮大号成绩卡及自己的历史，卡上有游戏、挑战码、档位、版本、完成数、分项、用时和保存状态。现场由同学展示并核对同一规则后比较；本地存储不承担其他电脑数据传输。每个本地玩家槽位/比较键保留首次正式尝试，重玩进入练习，改昵称不能释放次数；老师换轮次码再开始公平的新局。这是普通课堂约定，不提供防作弊认证。

正式时钟在动画暂停、站内切页、浏览器后台时继续；停的是画面与输入。返回已挂载页面保留局并先检查超时，边界上超时优先于新提交。`pagehide`（含 BFCache）、刷新、退出使所属新游戏正式局中断，不跨页面加载恢复比赛；旧展厅生命周期不据此改写。启动发现已有草稿只报告冲突，不因打开第二标签页就中断第一局。用户明确点击“结束未完成挑战”才将匹配草稿转为中断，告知也会结束仍在运行的旧窗口；次数锁保留。一个 origin 同时只开始一局正式挑战，承认本地存储无原子锁。

本地键 `science-arcade:local:v1`；读写失败仍可玩并显示“本机未保存”。按 origin 隔离，换浏览器、主机或端口会有另一份记录。只保留昵称代号、目标摘要、成绩与必要版本，最近 30 天/最多 200 条记录；不保存轨迹、录音或真实身份。清理只作用本键；损坏/新版本数据保留原值并提示，不覆盖未知存档。完整规则见[计分附录](../../engineering/2026-11-08-science-arcade-scoring.md)。

## 8. 采用的技能与协作交付

已读取并用于方案的核心组合：本地 `frontend-design`；GitHub `openai/plugins` 固定提交的 `web-game-foundations`、`game-ui-frontend`、`game-playtest`。分别用于视觉语言、规则/输入/保存边界、游戏舞台/HUD、真实玩法和截图验收。原文的通用引擎默认由本项目的 DOM/SVG 操作需求覆盖，不能声称这些技能强制推荐 SVG。GitHub 技能正文已核验，**尚未安装**；完整固定链接和证据在[技能附录](../../engineering/2026-11-08-science-arcade-skills.md)。

主负责人只控制本设计、共享接口、顺序和验收决策。6.1-sol 集成智能体实现导航/共用能力；01、02、03 智能体分别实现自己的游戏与约定文件；独立 6.1-sol 审查与试玩。共享文件一次只有一个所有者。执行前保存现有 Git 工作，每个可验收工作包通过检查后单独提交，最后做整体验证；本轮先保存规划文档。

完成条件：七路由与四组导航正确；三款完整可玩的游戏和因果反馈；原内容迁移完整；键盘/点击/拖拽等价；本地成绩可解释；正式计时/次数/存储错误边界正确；旧 01–04 回归通过。自动化与截图通过不等于儿童觉得好玩，现场试用后的理解度、操作负担和六分钟预算单独记录，再统一调整版本。
